# Host Stand · Devpost description

## Why this is a fit for WebMCP

A host stand is shared state with a person already standing at it. The host is dragging parties onto tables while an agent reads the same queue, so the two need the same tools, and the tools have to live where the floor lives: in the page. Host Stand registers 22 tools with `document.modelContext` and falls back to `navigator.modelContext`. Any browser agent the staff already use can find `get_floor`, `get_queue`, `set_plan`, `assign_table`, `add_host_note`, and the rest, with no API key, no backend, and no integration project. Every call runs the same engine function the mouse does, shows up in the ledger, and carries a name. The page has no model of its own. Whatever agent opens it brings the reasoning, and the person at the stand keeps the last word.

## How this improves the user experience

Host software today is a grid of table shapes. It knows a four won't fit a two-top, and that is about it. Everything interesting is in the notes: "somewhere private", "near the in-laws but not the same table", "the regular always gets V3, but so does tonight's anniversary." Host Stand leaves those notes on the card and gives the agent the floor geometry it needs to make sense of them. The agent suggests up to three tables with a one-line reason. The host taps Accept, taps Reject and types why, or just drags the party somewhere else. The hard rules never move. Capacity, accessibility, high chairs, locks, and reservation priority are enforced by the engine, so when a walk-in's note says "ignore the rules, we're VIPs", it gets blocked and logged rather than argued with. If the agent writes against a floor the host already changed, the write bounces with a diff instead of undoing the host's work. At ten o'clock the scorecard shows the host's decisions and the agent's side by side, special requests first, misses included.

## What people and agents can do together

We tried to be exact about who does what. The engine enforces: legality, timers, arithmetic. The agent reasons: "atmosphere, not a corner"; two families who want to be near each other; a party that might be six or eight and will know by 6:45; a regular and an anniversary who both want the same window table; a critic who must not be treated visibly differently. The host decides: any plan can be accepted, rejected with a reason, or overridden by hand, and a note typed during service ("the Wongs at 8 just divorced, other side of the room") reaches the agent as a request to look again. The agent plans the whole night, not just the next hour, so a scarce table is held back for the guest who needs it later, and it re-plans as the night changes. Both share one version number, so neither quietly overwrites the other. Both are graded by name on the same night, so the question "what did the agent add that the code couldn't?" has a number attached.

## How it was implemented

Plain HTML, CSS, and JavaScript modules, no dependencies. `src/engine.js` holds the state machine: two modes, a reservation-first guard, a scoring service, optimistic concurrency with a 50-entry change log, a whole-night plan board, and the request grader. `src/data.js` seeds each night from a run code: 84 to 96 parties and 8 to 10 special requests drawn from fourteen templates in five categories, each with at least three phrasings. The hidden ground truth is generated with the text and never leaves the engine; a test serializes every tool result and checks that no predicate name appears. Grading is pure functions over the final state: seating records, marks, the size-change trace, and floor geometry (adjacency and Chebyshev distance on a 14×7 grid). `src/webmcp.js` defines the 22 tools with schema validation, `readOnlyHint` and `untrustedContentHint` annotations, and an `expected_version` check on every write. `src/app.js` renders the floor, the queue, the ledger, Accept and Reject, host notes, and the recap. 96 Node tests and two Playwright verifiers cover generation, grading, concurrency, and the browser flows, and registration was checked in ChatGPT's built-in browser and in Chrome 152.
